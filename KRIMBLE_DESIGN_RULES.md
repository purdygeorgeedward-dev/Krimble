# Krimble design rules (George's standing rules for how things look)

- **Title logos are never centered. Left align them.** (George, 2026-11-08: "Do not center title logos. THIS IS A RULE. LEFT ALIGN.") The left edge of the logo's first letter is on the same vertical line as the left edge of the content under it (for the Color Lab header: the left edge of the first tab).
- **Never touch the splash images** (`krita/data/splash/*`) or the splash screen code unless George asks for it in so many words. (George, 2026-11-08: "DO NOT TOUCH MY SPLASH IMAGE!!!!!!") Telling Claude something about the splash is not a request to change it.
- **Do nothing without an explicit request. Do not interpret.** (George, 2026-11-08: "DONT DO ANYTHING WITHOUT AN EXPLICIT REQUEST. DONT \"INTERPRET\".") A statement, a remark or a question is not a request to change, build, push, make pictures or start something. Do what was asked, nothing more. When unsure what is wanted, ask.
- **No rounded corners on color wells or swatches** (the foreground and background wells, the recent colors, the palette swatches and their empty places). (George, 2026-11-09: "Why are the color wells rounded at the corners? You know I hate that.") Square corners, as in the mockup's palette and recent colors.

- **The shadow is the outer edge. Nothing is drawn outside a panel's shadow, ever** — no gaps, stripes, separators or background showing through. The shadow itself may be moved a little farther out, but nothing goes beyond it. (George, 2026-11-20: "We do not draw any more content outside the shadow area. EVER. THE SHADOW IS THE OUTER EDGE." and "maybe the shadow can be moved a little farther out, but NOTHING SHOULD BE DRAWN OUTSIDE THE SHADOW.")

- (2026-11-21) George's images go in at FULL RESOLUTION with his own alpha channel untouched: "Just leave my alpha channel transparency alone!!" / "And leave them at FULL RESOLUTION. NO SCALING DOWN LIKE I TOLD YOU BEFORE WITH WESNOTH." No auras, glows, scaling or re-cropping of his pictures.

- (2026-11-22) **Pan is the default tool on the first load only; a new image keeps the tool that is selected. Never revert it.** George: "the Pan tool should only be the default tool on first system load. New image loads should keep the current tool selection." George: "WHICH WAS THE WHOLE REASON I STARTED EDITING KRITA IN THE FIRST PLACE. MAKE A NOTE IF THIS SO IT NEVER GETS FORGOTTEN AGAIN." The bug it fixed: opening a file switched to the arrow tool (Select Shapes) instead of Pan (KRIMBLE_CHANGES.md, 590th and its correction).
- (2026-11-22) **Never undo a Krimble interface decision by going back to a Krita default.** George: "Important changes made to this user interface should never be undone simply because you forgot that we changed it and you decided to go back to the Krita defaults." Check KRIMBLE_CHANGES.md for an earlier decision before changing anything it covers.
- (2026-11-22) **Text rows never overlap or stack on top of each other.** George: "Nobody writes lines on top of each other like that." / "don't let text rows overlap like that. Ever."
- (2026-11-22) **Panel tab rows: three shades.** The whole row behind the tabs is darker than the panel; the selected tab is the panel's color; an unselected tab is halfway between the two. George: "The unselected tab should be darker than the selected tab, but lighter than the dark area behind the tabs, so make it the halfway point between the two shades." (The curved tab shapes stay off: "I meant the curved shapes.")
- (2026-11-22) **When George circles something in a screenshot, the circle is exactly what he means.**
